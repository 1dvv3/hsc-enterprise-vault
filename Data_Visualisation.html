Data Visualisation — HSC Final Notes

✅ Named topic in the Trial (Task 4). Six weeks. HSC 2025 exam: 14 marks across 6 questions. Key verbs: Describe, Explain. Online exam tools to be familiar with: screen design tool · drawing tool · spreadsheet tool Terminology: Terminology · Index: MOC

1. The Purposes of Data Visualisation

Data visualisations transform raw data into a visual format, enabling users to quickly and effectively understand complex information. Presenting data graphically provides clarity and insight that would be difficult to discern in text or numerical form.

The three purposes — memorise these

Purpose How it is achieved
Simplifying understanding Uses visual cues (colour, shape, size) so viewers identify patterns immediately without reading numbers · condenses large information into a compact format, reducing cognitive load · shows relationships by placing data points visually side by side · provides context by showing how individual points relate to the whole · makes data accessible to non-technical audiences
Telling a story Contextualises data rather than presenting isolated numbers · shows change over time and comparison between groups · highlights trends and patterns · shows relationships between variables · uses colour, layout and design to make data engaging and memorable · communicates not just what the data shows but what it means and what action follows
Highlighting significant results Emphasises key trends through line graphs · enables easy comparison through bar graphs where height indicates significance · makes outliers stand out · reveals patterns and correlations through heat maps and scatter plots · uses contrasting colour to distinguish high and low values

1.1 The Four-Step Answer Structure

Every "explain how this visualisation…" question uses the same shape:

1. WHAT      The visual shows…                    [identify the key feature]
2. HOW       This is shown by… which indicates…   [identify relationships]
3. WHY       This means that… because…            [cause and effect]
4. SO WHAT   Therefore, the visualisation…        [link to the purpose]

Model answer — simplifying understanding

This visual simplifies understanding by transforming complex data into an easy-to-read format using visual cues such as colours, shapes and sizes. The use of different colours and icons helps distinguish between categories, allowing viewers to quickly identify key information. Additionally, the visual condenses a large amount of data into a compact form, which reduces the need to interpret raw numbers. It also highlights relationships between data points by presenting them side by side, making comparisons and patterns easier to recognise. Therefore, the visual makes the data more accessible and allows users to quickly understand important information and trends.

Model answer — telling a story (Minard's Napoleon map)

This visual tells a story by showing Napoleon's army travelling to and from Russia while gradually decreasing in size. This is shown by the line becoming thinner as the journey progresses, indicating significant troop losses. The temperature graph also shows that as temperatures dropped, the size of the army decreased, highlighting a relationship between harsh weather conditions and losses. Additionally, the map provides context by showing the direction and location of the journey. Therefore, the visual effectively tells the story of the failed campaign by combining trends, relationships and contextual information to communicate the impact of the environment on the army.

Model answer — highlighting significant results

This visualisation highlights significant results by clearly comparing the popularity of different pizza toppings. This is shown through the use of a bar graph, where taller bars represent more popular toppings and shorter bars represent less popular ones. This makes it easy to identify key results, such as which toppings are most and least preferred. Additionally, some toppings stand out as outliers because they are significantly more or less popular than others, which helps to emphasise strong preferences. The visual also allows comparison between categories, such as meat and vegetable toppings, revealing patterns in consumer choices. Therefore, the visualisation effectively highlights significant results by using comparisons, visual features and patterns to draw attention to the most important insights in the data.

Two classic examples to name: Playfair's trade balance chart (shading shows the crossover from deficit to surplus) and Minard's Napoleon map (line thickness = army size, temperature graph beneath).

2. Software Tools

Tool type What it offers
Spreadsheets (Excel, Google Sheets) Built-in charting tools for quick visual representation · pivot tables and custom formulas to analyse complex data and highlight key insights
Creative design applications (Adobe Illustrator, Canva) Advanced design tools producing more sophisticated and visually appealing visualisations · add graphics, text and visual elements so output is both informative and engaging
Combining applications (Excel + Tableau + Google Data Studio) Integrate data from different sources, apply forecasting models, display real-time insights through dashboards · lets businesses compare current data against predicted trends

2.1 Evolution of Hardware and Software

Factor Impact on data analytics
Processing power Enables efficient analysis of large and complex datasets · supports advanced analytics using complex algorithms · enabled machine learning · allows real-time analytics · contributed to the rise of cloud computing, making advanced tools accessible without expensive hardware
Storage and memory Enables organisations to retain large datasets · supports more complex models and algorithms · enables machine learning, which relies on large training datasets · allows real-time analytics · enabled data warehousing — central storage supporting deeper analysis
Communication media Internet and mobile devices allow data collection from a wide range of sources · faster, more reliable communication makes real-time collection and analytics possible · enabled cloud computing · supports collaboration and sharing of insight · enhances visualisation and data-driven decision-making

The pattern in all three: each factor enabled bigger datasets → advanced analytics → machine learning → real-time → cloud. If you learn that chain you can answer any of the three.

3. Identifying Patterns

The five steps:

1. COLLECT DATA         from surveys, transactions or other sources
2. CLEAN AND ORGANISE   remove duplicates, handle missing values, transform format
3. EXPLORE              use visualisation, statistical analysis or ML to uncover insight
4. COMPARE DATASETS     across time periods, groups or categories
5. PREDICTIVE ANALYTICS use ML to identify relationships and predict future trends

4. OLAP — Online Analytical Processing

OLAP is a data analysis technique enabling business intelligence and decision-making. It is software allowing users to analyse and manipulate large, multi-dimensional datasets stored in a data warehouse.

How it works: data is organised into a cube-like structure, where each dimension represents a different aspect — time, geography, product, customer. The cube makes complex analysis fast.

The Four Techniques

Technique What it does Example Used for
Slicing Selects a single layer of the cube — filtering one dimension Only electronics sales in Australia Focusing on one category or condition
Dicing Analyses a subset across multiple dimensions Electronics vs clothing, in Sydney and Melbourne, during Q1 Side-by-side comparisons
Drill-down Breaks summary data into more detailed levels Country → state → city sales Finding specific contributors to a trend
Roll-up Combines detailed data into a higher-level summary Total sales across all cities or countries Getting the big-picture overview

Confusing pair — Slicing vs Dicing Slice = one dimension filtered, one flat layer of the cube. Dice = multiple dimensions filtered at once, a smaller sub-cube. One cut versus several.

Confusing pair — Drill-down vs Roll-up Drill-down goes more detailed (summary → specifics). Roll-up goes less detailed (specifics → summary). Opposite directions on the same hierarchy.

Worked scenarios:

Scenario Technique
Retail manager wants total sales per product category across all of Australia rather than individual cities Roll-up
Marketing analyst wants only electronics sales in Q1 2024, ignoring other categories Slicing
Manager knows electronics sell best overall and wants to know which specific city contributed most Drill-down
Company wants to compare electronics and clothing in Sydney and Melbourne during Q1 Dicing

5. Enterprise Data Warehousing

A data warehouse is a central storage system collecting and storing large amounts of data from different sources within an organisation. Unlike regular databases storing current, day-to-day data, a warehouse is designed to store historical data, allowing identification of trends and patterns over long periods.

Key features:

CENTRALISED           combines data from multiple sources
HISTORICAL            stores data over long periods
STRUCTURED, REFINED   cleaned and organised for analysis
SUPPORTS VISUALISATION used to create charts, dashboards and reports

How EDWs Improve Visualisation

Function Effect
Analysis of historical trends and patterns Stores large volumes over long periods, allowing analysis of seasonal sales or customer behaviour. Historical data is compared with current data, visualising change over time. Supports predictive insights, anticipating future demand
Correlation with current data Combines historical with real-time data, letting businesses compare past and present performance. Visualisation tools display these relationships, showing how current performance aligns with past patterns. Businesses adjust strategy when current trends diverge from history
Data refinement / optimisation Supports cleaning and transforming data — removing errors, duplicates and inconsistencies. Refined data improves the quality and reliability of visualisations, revealing hidden patterns

6. Data Integrity

Before creating any visualisation, assess data integrity to ensure the result is accurate and reliable.

Factor What it means The question to ask
Ownership Who controls and maintains the data — the collector, the owning organisation, or the visualisation team. Also determines who has authority to make corrections Are accountable people responsible for maintaining accuracy? Data with clear ownership is more trustworthy because someone is responsible for correcting errors
Source The origin — data type, format and method of collection, including processing, cleaning methods and storage location Does it come from a reliable, appropriate source? Data collected automatically from trusted systems is generally more reliable than unknown or manually collected data
Validation Verifying the accuracy and completeness of the data — checking anomalies, missing data, outliers and errors Is the dataset accurate and complete enough for meaningful visualisation? Poor validation leads to misleading graphs, incorrect trends and poor decisions
Risk The likelihood of data corruption, errors or privacy concerns — breaches, loss, unauthorised access Could the data expose sensitive information, become corrupted or be manipulated? High-risk data may not be safe or ethical to visualise publicly
Scope of visible information How much of the dataset the visualisation actually shows Is anything important being hidden by the framing?
Types and depth of insight What kinds of conclusions the data can legitimately support Can this data actually answer the question being asked of it?

6.1 Bias

Bias in data collection occurs when certain groups or variables are over- or underrepresented, producing skewed results that don't reflect reality.

Source of bias What to evaluate
Accuracy Are the underlying figures correct and complete?
Audience Is the visualisation shaped to tell a particular audience what it wants to hear?
Data source Does the source have an agenda, or systematically miss part of the population?
Unconscious bias Assumptions the designer isn't aware they're making — in what to include, how to scale axes, which comparison to draw

7. Big Data — The Five Vs

V Definition Handling
Volume The massive amount of data generated from web apps, IoT devices and transaction records. Traditional storage struggles at scale Cloud-based storage so valuable information isn't lost to storage limits
Velocity The speed at which data flows in — real-time social updates, high-frequency trading records. Provides opportunities for timely insight Stream processing frameworks and in-memory systems to capture and act in near real-time
Variety The many different formats — traditional structured, unstructured (free text, images, video), and semi-structured (JSON, XML) with organisational properties but no strict schema NoSQL databases and data lakes with schema-on-read frameworks
Veracity The accuracy and reliability of data. Great quantity from various sources means noise and errors leading to poor decisions Data cleaning, validation and verification tools
Value The real-world benefit — optimising operations, identifying marketing opportunities Advanced analytics, machine learning and AI transforming raw information into actionable insight

Data Science covers three Vs (volume, variety, velocity). Data Visualisation adds veracity and value. Know all five.

8. Interrogating a Data Visualisation

Interrogating means closely examining and analysing the information in a visualisation to draw insight, identify trends and make decisions.

The key questions:

What is the PURPOSE of the visualisation?
What TRENDS, PATTERNS or ANOMALIES are visible?
Are there any OUTLIERS or unusual data points?
What ASSUMPTIONS is the visualisation making?

8.1 Interpreting What You See

Step What to check
1. Understand the chart type Line → trends over time · Bar → compare categories · Pie → proportions of a whole
2. Examine the axes What is being measured · units used · scale of the graph
3. Look for patterns Trends · increases or decreases · clusters · gaps or unusual results
4. Contextualise Does the graph show the full story? Is more information needed? Are variables missing?

8.2 Aggregation

Aggregation means combining many data values into one summary value — sum, average (mean), count, median.

Benefits Limitations
Simplifies large datasets · makes trends easier to identify · provides a high-level overview May hide important details · can mask outliers or unusual results

8.3 Filtering

Filtering displays only specific parts of a dataset, helping users focus on relevant information.

Benefits Limitations
Simplifies large datasets · identifies trends and relationships · allows targeted analysis · makes dashboards interactive Important data may be hidden · can lead to biased conclusions if too much data is excluded

Common uses: customer feedback by age group · sales by region or product · web traffic by device type.

8.4 The Effect of Outliers

An outlier is a data point very different from the rest.

Outliers can reveal Outliers can damage
Errors in data entry · unusual but valid events · important insights Skew averages · distort trends · mislead viewers if ignored

What analysts should do: decide whether it is an error or a meaningful result, and investigate before removing it.

8.5 Reasoning

Reasoning means using logic and critical thinking to interpret data and draw conclusions.

Good reasoning includes Why it matters
Identifying trends — increases, decreases, seasonal patterns, relationships between variables Helps make informed decisions
Assessing causality — what may have caused this? Could there be multiple causes? Prevents incorrect conclusions
Avoiding bias — base conclusions on evidence, not assumption or opinion Supports evidence-based analysis
Questioning assumptions — does the visualisation show the full story? Guards against being misled

⚠️ Correlation is not causation. Two variables moving together does not prove one caused the other. Naming a possible third cause is a Band 6 move.

9. Dashboards

A dashboard is a single screen bringing together a small set of metrics with enough context to support a decision. It turns raw tables into ranked lists, small trends and clear status, so people know where to look first and what to do next.

9.1 The Narrative Approach

Dashboards work better when they read like a short story: give the user a setup, a change, and a next step. People remember sequences. If the screen says what changed and why, they stop hunting through charts and start acting.

9.2 Visual Hierarchy

People read what is heavy, close and high-contrast first. In left-to-right languages they scan in a Z: top-left → top-right → bottom-left → bottom-right. Put critical numbers on that path.

TOP     Status and targets — the "are we good?" line
MIDDLE  Trends and comparisons that explain the movement
BOTTOM  Details, owners and links that route follow-up work

9.3 Layout, Colour and Consistency

Principle Rules
Layout Use size and whitespace to signal priority, not as decoration. Keep a simple grid with even gutters — aligned cards read as orderly and trustworthy. Breaking the grid makes the page noisy and hides what matters
Colour Use colour as a signal, not decoration. Assign stable meanings (neutrals for chrome, one highlight for "pay attention", a reserved colour for risk). Restrict the palette — 8 to 12 hues is plenty, avoid the rainbow. Back up colour with a second cue (icons, patterns, labels) so colour-blind users aren't blocked. Test contrast in dark and light themes
Consistency Fix a grid, a spacing scale and a component set. Titles look the same everywhere, filters sit in the same place, legends behave the same. Don't surprise the user between tabs
Cognitive load Remove non-data ink. Shorten labels. Round numbers to useful precision. Hide rare controls behind "More". Keep navigation shallow
Limit choices Five precise filters beat fifteen vague ones. Ship with safe defaults so the first view is useful without clicks

9.4 Know Your Audience — The Six Questions

1. WHO     is the intended audience?
2. WHY     does this audience need to see this data? What decisions are they making?
3. WHAT    key metrics provide the insight needed to support those decisions?
4. HOW     will they use it — high-level monitoring, or drilling into detail?
5. WHEN    will it be used — daily, weekly, or only in specific situations?
6. DESIGN  how should it be structured to logically guide users through the data?

10. Evaluating Software Tools and UX

10.1 The Four Tool Categories

Tool Strength Weakness
Spreadsheets used to develop dashboards Accessible, familiar, low cost, quick to build Limited interactivity and scale; manual refresh
Presentation software used to present analysis Strong for narrative and static reporting Not live; data becomes stale immediately
Business analytics services, incl. 'as a service' products Scalable, live, professionally maintained, integrates sources Ongoing subscription cost; data leaves the organisation
Custom software solutions Exactly fits the enterprise's needs High development cost, long build time, ongoing maintenance burden

10.2 Evaluating User Experience

Analysis breaks something into components to understand how it works. Evaluation takes those findings and assesses their value, quality or effectiveness against criteria. Analysis is the breakdown. Evaluation is the judgement.

Criterion Guiding question Evaluation method
Clarity Is it easy to understand? Are labels and headings clear? Observation
Usability Can users quickly find important information? Are filters and navigation easy? Task-based testing
Accuracy Does it display information correctly, without misleading scales or missing data? Heuristic evaluation
Accessibility Is text readable? Are colours distinguishable? Would colour-blind users understand it? User feedback
Efficiency Can users gain insight quickly? Is there unnecessary clutter? Time on task
Aesthetics Is it visually appealing and organised? Surveys and feedback
Context and purpose Does it explain the purpose of the data clearly? Qualitative feedback

10.3 UX Factors in the Syllabus

Factor Meaning
Relevance to the audience The metrics shown must match the decisions that audience actually makes
Audience interpretation How the audience will read it — including how they might misread it
Customisation Whether users can tailor views, filters and layouts to their own needs
Live analysis Whether data updates in real time or is a static snapshot

11. Developing a Visualisation

The process:

1. RESEARCH AND SOURCE   locate relevant, reliable datasets for the scenario
2. ORGANISE AND STORE    structure the data appropriately, securely
3. GRAPHIC DEVELOPMENT   apply design principles and digital tools
4. DESIGN AND DEVELOP    represent trends, patterns and relationships
                         and illustrate predictive analysis with big data
5. SECURE                implement cybersecurity and data backup

11.1 Maintaining Data Security

Method What it covers
Cybersecurity Access control, encryption, authentication, firewalls, protecting against unauthorised access and breach
Data backup Regular copies stored separately so data can be restored after loss, corruption or attack

12. Confusing Terms — Quick Reference

Term Meaning Don't confuse with
Slicing Filter one dimension Dicing — filter multiple dimensions
Drill-down Summary → detail Roll-up — detail → summary
Aggregation Combining values into one summary Filtering — showing only part of the data
Analysis Breaking into components Evaluation — judging against criteria
Data warehouse Historical data, central, for analysis Database — current, day-to-day operations
Structured data Fixed schema Semi-structured — JSON, XML · Unstructured — text, images
Outlier A point far from the rest An error — an outlier may be valid
Correlation Two variables move together Causation — one causes the other
Line chart Trends over time Bar chart — comparing categories · Pie chart — proportions
Ownership Who is accountable for the data Source — where it came from
Validation Checking accuracy and completeness Verification — confirming it matches the original
Infographic Static, single point in time Dashboard — live, interactive, decision-oriented
